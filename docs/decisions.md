## 決定事項

| 日付 | 決定 | 理由・補足 |
| --- | --- | --- |
| 2026-10-10 | 「緊張」は重心の位置ではなく「重さと場所の偏り」（重さで重み付けした場の値 − 単純平均）で測る | 重心の位置で測ると「均衡」ルールと真っ向からぶつかり、どちらも効かなくなったため。カンディンスキーの言う安定は「重いものが下にある配置」 |
| 2026-10-10 | 均衡の目標点は、緊張に合わせて上下にずらす（安定なら画面高さの 10% 下） | 重いものが下にあれば重心も下がるのが自然なため |
| 2026-10-10 | 大きさの変更は高コスト（フィボナッチ 1 段 ＝ 画面短辺の 45% 移動に相当） | 初期設定でユーザーが描いた大きさを勝手に変えないため。緊張・均衡を強めたときだけ大きさも変わる |
| 2026-10-10 | 「枠」ルールを追加。上 100px・下 72px は操作パネル分として図形を置かない | 長い直線のはみ出しと、図形がツールバーの下に隠れる問題への対応 |
| 2026-10-10 | 局所探索は「時間」ではなく「評価回数」で打ち切る（上限 12,000 回） | 結果を毎回同じにするため（テスト・再現性）。60 図形でおよそ 30ms |
| 2026-10-10 | 初期値：均衡 0.4（やや動的）、緊張 -0.3（やや安定）、各ルールの重みは `DEFAULT_WEIGHTS` | 何もしなくても落ち着いた構図になり、強めると性格がはっきり変わる |
| 2026-10-09 | 色調モード（カラー／モノトーン／モノトーン＋1 色）を加える | ユーザー要望。色を外すと重さが明暗と面積だけで決まり、別のバランスになる。`roadmap.md` §2-6 |
| 2026-10-09 | プリセットの自動切り替え（指揮者）を作る。引き金は主に「飽き」、行き先は主に「形の種類と数」 | ユーザー要望（「飽きたころに」「形態の種類や数に従って」）。`roadmap.md` §2-5 |
| 2026-10-09 | 理論を「師匠プリセット」にまとめて見せる | 30 を超えるスイッチを見せないため、また一度に効く理論を絞って美しさを保つため |
| 2026-10-09 | エンジンを「ルール＋コスト関数＋局所探索」に作り直す（フェーズ 1） | 理論が約 33 個に増えると、今の順番処理では破綻するため |
| 2026-10-09 | 理論は平面だけでなく、立体作品（家具・日用品・玩具）からも抽出する | ユーザー要望。`bauhaus-theory.md` §10 |
| 2026-10-09 | アイコン・スプラッシュ画像はアプリの全体像が固まってから作る | ユーザー指示。生成スクリプトだけ `assets/src/` に残してある（実行すると `public/` も書き換わるので注意） |
| 2026-10-09 | アプリ ID は `com.lomaloma.bau` | ユーザーが決定（`com.onepine.bau` から変更）。ストア公開後は変更不可 |
| 2026-10-09 | ストア配信は Capacitor で今の Web アプリを包む | コードをそのまま使え、iOS / Android の両方に出せる |
| 2026-10-09 | Godot への移植は Web 版の完成度を上げた後に検討する | 理論エンジンは描画から独立した純粋関数なので移植しやすい。移植するならローカル（Godot が入った PC）で行う |
| 2026-10-09 | Unreal Engine は使わない | 2D の幾何学表現に過剰、Web 書き出しの公式サポートなし、アプリが巨大になる |
| 2026-10-09 | クラウドセッションで可能な限り進め、最終的にターミナルの Claude Code に引き継ぐ | ユーザー方針。実機ビルド・実機テスト・ストア申請はローカルで行う |

## 未確認・既知の制限（v0.1 時点）

- **2 本指の拡大・回転**：自動テストで再現できず、実機で未確認
- **PWA**：manifest・Service Worker・アイコンはあるが、ホーム画面へのインストールとオフライン起動は実機で未確認
- **iOS / Android アプリ**：ネイティブプロジェクトは生成済み・同期済みだが、ビルドも実機での動作も未確認（クラウドには Android SDK・Xcode がない）
- **ネイティブの書き出し**：共有シート経由の保存は実装済みだが未確認
- **アイコン・スプラッシュ**：`public/icon-*.png` は仮のもの。ネイティブ側は Capacitor の初期画像のまま
- **原典の確認**：archive.org などにクラウドからアクセスできず、理論の一部は二次資料のみで確認（`bauhaus-theory.md` の 🔶 印）

## 環境についてのメモ

- クラウドセッションはユーザーの PC にアクセスできない。成果は GitHub の作業ブランチ経由で受け渡す
- ビルドの自動化には GitHub Actions が使える（Android は Linux、iOS は macOS のビルド環境。macOS は無料枠の消費が約 10 倍）
- ローカルで Claude に作業させるには、Claude Desktop アプリか、PC のターミナルで `claude remote-control`
